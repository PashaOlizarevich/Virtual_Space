# Git и жизненный цикл задач

Для feature, refactor и bugfix обязательно сначала прочитай `docs/git-flow.md` и следуй ему.

## Перед изменениями

- Выполни `git status --short` и `git branch --show-current`.
- Не изменяй код напрямую в защищённых ветках `main`, `master` и `dev`.
- Считай существующие незакоммиченные изменения пользовательскими, пока не доказано обратное.
- Если рабочее дерево не чистое, не переноси чужие изменения в новую ветку или worktree без проверки.
- Для одиночной последовательной задачи создай отдельную ветку в текущем каталоге.
- Для параллельной работы агентов или процессов используй отдельную ветку и Git worktree для каждого исполнителя.

## Во время работы

- Не используй `git reset --hard`, `git checkout --`, force push и другие destructive-команды.
- Не форматируй и не переписывай несвязанные файлы.
- После завершения проверенного логического блока создавай атомарный savepoint-коммит.
- В один коммит включай только связанные изменения и используй формат сообщений из `docs/git-flow.md`.
- Не добавляй в коммит секреты, `.env`, временные файлы и посторонние изменения.

## Завершение

- Проверь итоговый diff, статус, тесты, сборку и отсутствие секретов.
- Создай финальный коммит в рабочей ветке, если после последнего savepoint остались изменения.
- Остановись и передай пользователю отчёт с веткой, коммитами, файлами, проверками и ограничениями.
- Не выполняй `push`, `merge`, `rebase`, удаление ветки/worktree и создание Pull Request без прямого разрешения пользователя.
- Разрешением на слияние считается явная команда пользователя, например: `Да, сливай`.
