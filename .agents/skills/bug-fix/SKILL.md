# Исправление ошибки

## Назначение

Устранить подтверждённую первопричину без маскировки симптомов и побочных изменений.

## Порядок действий

1. Воспроизвести ошибку безопасным минимальным сценарием и сохранить точное поведение.
2. Проследить поток от симптома к источнику через код, типы, данные, логи и тесты.
3. Сформулировать конкретную первопричину и границы влияния.
4. Добавить failing regression-тест, когда это практично.
5. Внести минимальное исправление в правильном слое.
6. Повторить воспроизведение, запустить затронутые и общие проверки.

## Ограничения

- Не отключать проверку, не поглощать исключение и не добавлять случайный fallback вместо причины.
- Не проводить несвязанный рефакторинг и не изменять данные без подтверждения.
- Не объявлять дефект исправленным без проверяемой улики.

## Критерии завершения

- Первопричина объяснена, исходный сценарий проходит, regression-тест защищает поведение.
- Новых ошибок lint/typecheck/test/build нет либо ограничения явно указаны.
