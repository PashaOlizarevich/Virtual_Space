# Разработка API

## Назначение

Создать тонкую безопасную transport-границу над доменным сервисом.

## Порядок действий

1. Найти вызывающий код, доменный модуль, существующие схемы, DTO и правила ошибок.
2. Выбрать Server Action для собственного UI или Route Handler для HTTP/внешнего клиента.
3. Определить Zod-схему входа, авторизацию, idempotency/transaction требования и DTO ответа.
4. Реализовать бизнес-операцию в service, а transport оставить для parse/auth/map.
5. Обработать ожидаемые ошибки без утечки внутренних деталей.
6. Покрыть success, invalid input, unauthorized/forbidden и доменные конфликты.
7. Выполнить `$security-review` для endpoint/action перед завершением.

## Ограничения

- Не использовать UI-скрытие как авторизацию и не возвращать Prisma-модель.
- Не принимать цену, итог заказа или роль клиента как источник истины.
- Не смешивать внешние SDK с доменной логикой; использовать адаптеры.

## Критерии завершения

- Контракт валидирован, права проверены на сервере, response DTO стабилен.
- Тесты endpoint/action и стандартные проверки проходят.
