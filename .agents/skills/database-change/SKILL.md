# Изменение базы данных

## Назначение

Изменить модель данных безопасно, совместимо и с явными инвариантами.

## Порядок действий

1. Изучить требования, текущую Prisma schema, migrations, queries и DTO.
2. Оценить данные, nullable/default/backfill стратегию, индексы, ограничения и откат.
3. Внести минимальное изменение схемы и адаптировать services/mappers/contracts.
4. Создать миграцию только если это входит в задачу и целевая среда известна.
5. Добавить тесты инвариантов и транзакционного поведения.
6. Для чувствительных данных проверить доступ, раскрытие, mass assignment и destructive-риск через
   `$security-review`.
7. Запустить Prisma validate/generate, typecheck, тесты и build.

## Ограничения

- Не выполнять reset, destructive migration, seed или production-запросы без разрешения.
- Не удалять используемое поле без совместимого перехода.
- Не использовать неточные числа для денег и raw SQL без обоснования.

## Критерии завершения

- Схема выражает инварианты, миграционный путь безопасен, код и DTO согласованы.
- Prisma-проверки и тесты проходят; риски данных явно описаны.
