# Проверка изменений

## Назначение

Найти конкретные проблемы, влияющие на корректность, безопасность и сопровождение; не редактировать
код, если исправление отдельно не запрошено.

## Порядок действий

1. Определить базу и область review; прочитать diff вместе с окружающим кодом и требованиями.
2. Проследить потоки данных, права, ошибки, состояния UI и миграционные последствия.
3. Проверить архитектурные границы, типы, валидацию, доступность, тесты и совместимость.
4. Подтвердить замечание конкретным сценарием и точной ссылкой на файл/строку.
5. Ранжировать findings по риску; не перегружать отчёт вкусовыми предпочтениями.
6. Если изменения затрагивают чувствительную область, применить `$security-review` и выделить его
   findings отдельной категорией.
7. Указать выполненные проверки и остаточный риск.

## Ограничения

- Не изменять файлы, не создавать commit/PR и не утверждать непроверенные проблемы.
- Не считать прохождение тестов доказательством отсутствия дефектов.
- Не скрывать критичное замечание внутри общего резюме.

## Критерии завершения

- Findings перечислены по убыванию серьёзности с причиной, сценарием и местом.
- Если проблем нет, это сказано явно вместе с проверенной областью и остаточными рисками.
