# 2. Цель проекта

Разработка небольшого интернет-магазина с базовым функционалом электронной коммерции и возможностью дальнейшего масштабирования.

Основная задача проекта — создать полноценное веб-приложение, включающее:

- каталог товаров;
- страницы товаров;
- корзину;
- оформление заявки;
- административную панель;
- управление товарами;
- управление заказами.

Архитектура приложения должна предусматривать дальнейшее развитие:

- добавление пользователей;
- онлайн-оплату;
- систему отзывов;
- рекомендации товаров;
- AI-функции;
- расширенную аналитику.

# 11. Проверка актуальности товаров в корзине:

 **Проверка актуальности товаров в корзине**
 
 Перед отображением корзины и особенно перед оформлением заявки система должна проверять актуальность товаров на сервере.
 
 Проверяется:
 
 - существует ли товар;
 - доступен ли товар;
 - актуальна ли цена;
 - актуальны ли выбранные характеристики и варианты товара.
 
 Если товар был удалён администратором:
 
 - товар помечается как недоступный;
 - пользователь получает уведомление;
 - товар исключается из активной корзины;
 - остальные товары корзины сохраняются.
 
 Если цена товара изменилась:> 
 - пользователю отображается актуальная цена;
 - перед оформлением заявки пользователь должен подтвердить изменение стоимости.
 
  Перед созданием заявки Backend выполняет финальную проверку всех товаров корзины. Только после успешной проверки создаётся заявка.

# 14.3 Управление заказами

Управление статусами заказа

Каждая созданная заявка получает начальный статус:

Новый

После создания заявки статус автоматически устанавливается в «Новый».

Администратор может изменять статус заказа через административную панель.

Доступные статусы:

- Новый
- В обработке
- Завершен
- Отменен

### Сценарий изменения статуса

Новый
↓
В обработке
↓
Завершен

При необходимости администратор может установить статус:

Новый → Отменен
В обработке → Отменен

### Кто изменяет статус

Статус изменяется только администратором через административную панель.

Пользователь не может самостоятельно изменить статус своего заказа.

### Отображение статуса

В административной панели статус отображается в списке заказов и внутри страницы конкретного заказа.

Если в будущем будет реализован личный кабинет пользователя, пользователь сможет видеть текущий статус своего заказа.

### Изменение статуса

При изменении статуса:

1. Администратор выбирает новый статус.
2. Frontend отправляет запрос на Backend.
3. Backend проверяет права администратора.
4. Backend обновляет статус заказа в PostgreSQL.
5. Обновленный статус отображается в административной панели.

### История статусов

Для дальнейшего развития проекта рекомендуется сохранять историю изменения статусов:

- предыдущий статус;
- новый статус;
- дата изменения;
- администратор, который изменил статус.

Это позволит в будущем отследить историю обработки заказа.

# 18. Сохранение корзины пользователя

Корзина должна сохраняться между сессиями пользователя.

### Неавторизованный пользователь

Для гостя корзина хранится в Zustand и сохраняется в localStorage с помощью persist middleware.

Схема:

Zustand
↓
persist middleware
↓
localStorage

После перезагрузки страницы или повторного открытия сайта корзина восстанавливается.

### Авторизованный пользователь

Для авторизованного пользователя корзина хранится:

- в Zustand — для текущего состояния интерфейса;
- в PostgreSQL — для постоянного хранения.

Корзина связывается с пользователем через userId.

Схема:

Zustand
↓
API
↓
Prisma
↓
PostgreSQL
↓
userId

При авторизации локальная корзина синхронизируется с корзиной пользователя в базе данных.

При выходе из аккаунта данные корзины пользователя не удаляются.

При повторной авторизации корзина загружается из базы данных и восстанавливается в Zustand.
